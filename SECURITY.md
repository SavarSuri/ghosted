# Security Policy

## Reporting a vulnerability

If you find a security issue in GhostED, email **savarsuri06@gmail.com** with "GhostED security" in the subject.

Please include what you found, the steps to reproduce it, and what an attacker could do with it. A proof of concept helps.

Please do not open a public issue for a security bug.

This is a personal project, not a company, so there is no bounty and no SLA. I will acknowledge your report and I will credit you in the fix unless you'd rather I didn't.

## Scope

In scope: the live application at ghosted-eta.vercel.app and the code in this repository.

Out of scope: Supabase and Vercel infrastructure (report those to the vendors), findings that require physical access to a user's device, and reports generated by an automated scanner with no demonstrated impact.

## A note on the anon key

The Supabase anonymous key is public by design and is visible in the page source. That is how the client is intended to work. Security is enforced by row-level security policies on the database, which scope that key to `SELECT` and `INSERT` only.

Finding the key in the source is not a vulnerability. A policy that lets it do more than read and insert would be. If you find one, please tell me.
